# Devnet SOL Trading Platform — Technical Specification

## Project Overview

A trading platform built on Solana where users trade devnet SPL tokens, with a fee-gated bridge to real mainnet SOL value. The core innovation is a **whitelist/blacklist bucket system** that lets the platform accept freely-obtained devnet SOL (from faucets, P2P transfers) without taking on infinite redemption liability.

The platform is structured as a permissionless AMM (bonding curves + liquidity pools, pump.fun style) where every devnet SOL has a redeemability status tracked per-wallet by the platform's on-chain program.

---

## Core Economic Model

### The Problem We're Solving

Devnet SOL is fungible and freely available from faucets. A naive "devnet-to-mainnet exchange" platform would be drained instantly: attackers would farm faucet SOL and redeem it for real money.

We can't distinguish faucet-origin devnet SOL from platform-issued devnet SOL on-chain (they're the same asset). So instead of trying to mark the SOL itself, we mark **the redeemability status of each user's holdings** in our program state.

### The Bucket Model

Every user has two buckets of devnet SOL tracked by the platform program:

- **Blacklisted**: devnet SOL that hasn't paid an activation fee. Includes faucet deposits and P2P-received SOL. Cannot be redeemed.
- **Whitelisted**: devnet SOL that has paid the activation fee (or is the profit/proceeds from whitelisted activity). Can be redeemed for mainnet SOL at the redemption rate.

Each launched token also has whitelisted/blacklisted bucket tracking per-user.

### Fee Structure

- **Activation fee**: 1% of devnet SOL value, paid in **mainnet SOL**, charged when blacklisted SOL is first used in a trade
- **Redemption rate**: 0.8% of whitelisted devnet SOL value, paid out in mainnet SOL
- **Spread**: 0.2% per activation cycle = platform margin
- **Treasury split**: 80% of mainnet fees collected go to a smart contract (PDA) for redemption reserves; 20% goes to a team wallet

### Fee Mechanics (Important Details)

1. Fee fires **once per SOL**, the first time it's used in a trade
2. After fee payment, SOL becomes whitelisted in the user's bucket
3. Subsequent trades using already-whitelisted SOL pay no fee
4. If a trade exceeds the user's whitelisted balance, fee fires only on the excess (the blacklisted portion being used)
5. **Profits from trading whitelisted SOL are automatically whitelisted** (they came from whitelisted activity)
6. **Losses reduce whitelisted balance, floored at zero** (spot trading only, no negative balances, no clawback into blacklist)
7. P2P transfers received are added to the recipient's **blacklisted** bucket (no fee was paid)

### Worked Examples

**Example 1: Basic activation**
- User has 100 devnet SOL from faucet (100 blacklisted, 0 whitelisted)
- User trades 10 devnet SOL for token X
- Fee charged: 0.1 mainnet SOL (1% of 10 devnet)
- After trade: 90 blacklisted devnet, 0 whitelisted devnet, 10 whitelisted token X (whatever quantity 10 SOL bought)
- Token X 3x's. User sells it back for 30 devnet SOL
- After sell: 90 blacklisted devnet, 30 whitelisted devnet
- User redeems 30 whitelisted devnet → receives 0.24 mainnet SOL (0.8% of 30)

**Example 2: Trading within whitelist limit**
- User has 30 whitelisted, 70 blacklisted
- User trades 25 devnet SOL → no fee (within whitelist)
- After trade: 5 whitelisted devnet remaining, 70 blacklisted devnet, plus token holdings

**Example 3: Trading exceeds whitelist**
- User has 30 whitelisted, 70 blacklisted
- User wants to trade 35 devnet SOL
- Fee charged: 0.05 mainnet SOL (1% of the 5 SOL excess from blacklisted)
- After trade: 0 whitelisted devnet remaining, 65 blacklisted devnet, plus token holdings (with 35 SOL worth whitelisted)

**Example 4: Loss accounting**
- User has 30 whitelisted, trades 30 into a token, token goes to 0
- Whitelisted balance after: 0 (floor)
- No carry-over to blacklisted, no negative balance

### Solvency Invariant

At all times, the smart contract must hold:

```
mainnet_treasury >= 0.008 × total_whitelisted_devnet_supply
```

If this invariant ever fails, redemptions halt. The contract tracks `total_whitelisted_supply` as a global counter, incremented on every fee activation, decremented on every redemption.

### Why This Is Wash-Trade Resistant

Every devnet SOL that becomes whitelisted paid a 1% fee at some point in its history. Redemption pays 0.8%. Platform always nets 0.2% per activation cycle, regardless of:

- Self-trading across multiple wallets (the SOL has to flow through someone's blacklisted bucket to enter the system, paying the fee)
- Collusive price manipulation (the fee is on volume activated, not on price)
- P2P transfers (received SOL lands as blacklisted and must pay fee to become tradeable again)

The bonding curve mechanism (see AMM section) further prevents profit-manufacturing because deterministic curves make wash trading loss-making due to slippage.

## AMM Architecture

### Token Launch Flow

Users can create new SPL tokens on devnet through the platform. The platform program is the sole authority to create trading pools for tokens launched through it.

Token metadata: name, ticker, image, description. Stored via Metaplex Token Metadata Program with the platform program as update authority during the bonding curve phase.

### Bonding Curve Phase (pump.fun style)

New tokens start on a constant-product bonding curve:

```
x * y = k
```

Where:
- `x` = virtual devnet SOL reserve
- `y` = real token reserve
- `k` = constant

The curve is held in a PDA controlled by the platform program. All buys and sells route through the curve. Price increases as users buy, decreases as they sell.

**Initial parameters per token:**
- Virtual SOL reserve: 30 devnet SOL (sets the initial price floor)
- Real token reserve: 1,000,000,000 tokens (1B supply standard)
- Graduation threshold: when real devnet SOL deposited reaches ~85 devnet SOL (configurable)

**Why constant-product on bonding curve:** deterministic pricing makes wash trading lose money to slippage. Attacker can't manufacture profit by trading with themselves.

### Graduation to Liquidity Pool

When a token's bonding curve crosses the graduation threshold:

1. All devnet SOL in the curve is deposited into a new LP
2. A corresponding amount of tokens (calculated from the curve's final state) is paired into the LP
3. Remaining unsold tokens in the curve are burned
4. Initial LP tokens are locked for a minimum period (e.g., 7 days) to prevent immediate rug pulls

### LP Phase

Standard constant-product AMM (x*y=k) for graduated tokens, paired with devnet SOL. Anyone can add/remove liquidity. LP tokens issued for liquidity provision. Trading on LPs follows the same whitelist/blacklist rules as bonding curve trading.

### Whitelist/Blacklist Integration with AMM

Every trade through the AMM (curve or LP) hits the user state account:

1. Check user's whitelisted devnet SOL balance
2. If trade size ≤ whitelisted: no fee, proceed
3. If trade size > whitelisted: charge 1% mainnet fee on the excess, mark that excess as whitelisted
4. Execute the swap
5. Update user's whitelisted token balance (received tokens are whitelisted if they came from whitelisted SOL)
6. On sell side: received devnet SOL is whitelisted

Token bucket tracking is per-(user, token) pair. Selling whitelisted tokens yields whitelisted devnet SOL.

## On-Chain Program Structure

Framework: **Anchor** (Solana's standard framework, simplifies PDA management).

### Account Structures

```rust
// Global platform state
#[account]
pub struct Platform {
    pub admin: Pubkey,
    pub team_wallet: Pubkey,
    pub treasury_pda: Pubkey,           // PDA holding mainnet SOL reserves
    pub activation_fee_bps: u16,        // 100 = 1%
    pub redemption_rate_bps: u16,       // 80 = 0.8%
    pub team_split_bps: u16,            // 2000 = 20%
    pub total_whitelisted_devnet: u64,  // global counter for solvency check
    pub total_mainnet_reserves: u64,    // global counter
    pub paused: bool,
    pub bump: u8,
}

// Per-user state (PDA seeded by user pubkey)
#[account]
pub struct UserState {
    pub owner: Pubkey,
    pub whitelisted_devnet: u64,
    pub blacklisted_devnet: u64,
    pub bump: u8,
}

// Per-user per-token state (PDA seeded by user + token mint)
#[account]
pub struct UserTokenPosition {
    pub owner: Pubkey,
    pub token_mint: Pubkey,
    pub whitelisted_amount: u64,
    pub blacklisted_amount: u64,
    pub bump: u8,
}

// Per-token state
#[account]
pub struct TokenLaunch {
    pub mint: Pubkey,
    pub creator: Pubkey,
    pub created_at: i64,
    pub curve_state: Pubkey,         // PDA for bonding curve
    pub graduated: bool,
    pub lp_address: Option<Pubkey>,  // populated after graduation
    pub bump: u8,
}

// Bonding curve state (PDA per token)
#[account]
pub struct BondingCurve {
    pub token_mint: Pubkey,
    pub virtual_sol_reserve: u64,
    pub real_sol_reserve: u64,
    pub virtual_token_reserve: u64,
    pub real_token_reserve: u64,
    pub graduation_threshold: u64,
    pub graduated: bool,
    pub bump: u8,
}

// LP state (post-graduation)
#[account]
pub struct LiquidityPool {
    pub token_mint: Pubkey,
    pub sol_reserve: u64,
    pub token_reserve: u64,
    pub lp_mint: Pubkey,
    pub total_lp_supply: u64,
    pub bump: u8,
}
```

### Key Instructions

**Phase 1: Bucket tracking**

- `initialize_platform`: admin sets up Platform account, treasury PDA, parameters
- `initialize_user_state`: user creates their UserState PDA
- `deposit_devnet`: user transfers devnet SOL to platform escrow, added to blacklisted bucket
- `redeem`: user burns whitelisted devnet SOL, receives 0.8% in mainnet SOL from treasury PDA. Enforces solvency invariant before payout.

**Phase 2: Bonding curve trading**

- `launch_token`: creates SPL mint + TokenLaunch + BondingCurve PDAs. Creator can optionally seed initial liquidity.
- `buy_curve`: user buys tokens from bonding curve. Checks/updates whitelist buckets. Charges activation fee if blacklisted SOL is used. Calculates token output via constant product.
- `sell_curve`: user sells tokens back to curve. Updates buckets, returns devnet SOL to user.
- `check_graduation`: callable by anyone; if curve crosses threshold, triggers graduation

**Phase 3: LP trading**

- `graduate_token`: moves curve liquidity into LP, mints LP tokens to a locked vault for the initial period, burns remaining curve tokens
- `swap_lp`: trade on the LP, same whitelist/blacklist rules as curve trades
- `add_liquidity`: deposit SOL+token, receive LP tokens
- `remove_liquidity`: burn LP tokens, withdraw proportional SOL+token

**Phase 4: P2P handling**

- Transfer hook on the wrapped devnet SOL token (Token-2022): on any external transfer, recipient's UserState gets the amount added to blacklisted bucket. This handles P2P transfers cleanly.

### Treasury PDA

A single PDA holds all mainnet SOL reserves. It's controlled by the platform program. Only `redeem` can withdraw from it, and only after the solvency check.

The 20% team split happens at fee collection time: when a user pays a 1% activation fee, 0.8% goes to treasury PDA, 0.2% goes to team wallet immediately.

## Token Choice: Token-2022 with Transfer Hooks

Use **Token-2022** (SPL Token Extensions) for the platform's internal accounting tokens, specifically because of **transfer hooks**.

Transfer hooks let us intercept every transfer of a token and run custom program logic. This is how P2P transfers automatically route through our bucket-update logic.

**Tokens to wrap with Token-2022:**
- A wrapped devnet SOL token (we control the mint, 1:1 backed by actual devnet SOL deposits)
- Optionally, the launched project tokens, so we can enforce bucket tracking on token-side too

Users deposit devnet SOL → receive wrapped devnet SOL (wDSOL) into their wallet, blacklisted. Trades happen using wDSOL. Redemption burns wDSOL and pays mainnet SOL.

This design means users actually hold their tokens (good UX, real ownership) but the bucket state travels with the tokens via the transfer hook.

## Open Design Decisions (For Future Discussion)

1. **Graduation threshold tuning**: 85 devnet SOL is a placeholder. Should be calibrated based on expected launch volume.
2. **LP lock period**: 7 days is a placeholder. Could be longer for stronger anti-rug.
3. **Token creation fee**: Should creating a new token cost a small mainnet SOL fee to prevent spam launches? Probably yes.
4. **Maximum trade size per block**: Should the platform rate-limit huge trades to prevent griefing?
5. **Margin sustainability**: 0.2% margin is thin. Model expected gas costs and volume to verify viability; consider raising activation fee to 1.2% or 1.5% if needed.
6. **Treasury upgrade path**: How does the program upgrade work if we need to change parameters? Multisig admin? DAO governance later?

- Use **Metaplex Token Metadata Program** for token metadata
- All math involving SOL amounts must use `u64` and check for overflow (use `checked_*` arithmetic)
- All PDA seeds documented per account
- Every instruction has corresponding integration tests in `tests/`
- Frontend will be a separate workspace (Next.js + `@solana/wallet-adapter`)
- Indexer is separate again (probably Helius webhooks → Postgres)
- Start with Phase 1; do not move to Phase 2 until bucket math is provably correct under tests

## Glossary

- **Devnet SOL**: SOL on Solana's devnet (test) network. Free to obtain from faucets. No real value.
- **Mainnet SOL**: Real SOL on Solana mainnet. Has real value.
- **Blacklisted SOL**: Devnet SOL in a user's bucket that hasn't paid the activation fee. Not redeemable.
- **Whitelisted SOL**: Devnet SOL that has paid the activation fee (or is profit from whitelisted activity). Redeemable.
- **Activation fee**: 1% mainnet SOL paid when blacklisted SOL is first used in a trade.
- **Redemption**: Burning whitelisted devnet SOL to receive 0.8% of its value in mainnet SOL.
- **Bonding curve**: A pre-LP price discovery mechanism using constant product math.
- **Graduation**: When a token's bonding curve hits the threshold and migrates to a full LP.
- **LP**: Liquidity pool, a standard constant-product AMM.
- **wDSOL**: Wrapped devnet SOL, the Token-2022 wrapper that carries bucket state via transfer hooks.
- **Treasury PDA**: The Program Derived Address that holds mainnet SOL reserves for redemptions.
